# 🏠 Buy or Rent Japan — 日本买房 vs 租房计算器

> **版本：V3.4.6（计算说明书 / Calculation Specification）**  
> **适用范围：** 日本二手公寓、买入后自住、在选定观察年份卖出结清，与同期租房并投资进行比较。  
> **实现：** `public/index.html`，原生 HTML / CSS / JavaScript，无后端数据库。

本 README 依据 **V3.4.6 实际源代码**整理，描述程序**当前究竟怎么算**，而非宣称所有公式和假设都符合真实银行、税务或房地产市场。已识别的缺陷列在文末「待修正项」，不能忽略。

## 1. 使用说明与比较口径

1. 设置房价、**买入时房龄**、首付金额、贷款利率及期限等。金额输入除特殊注明外均为 **万日元**。
2. 设置买房和租房各自的实际支出、投资年化收益，以及贷款减税模式。
3. 选择 **观察年份 `Y`（1～35年）**。模型假定在第 `Y` 年年末**卖房、结清剩余贷款**，与同日一直租房所积累的相对金融资产比较。
4. 结果属于**相同资金基准下的差额投资比较**，不是完整家庭资产负债表。无需输入共同月预算，也**不能**凭此判断贷款可负担性。
5. 每5年表显示第5、10、15、20、25、30、35年。**市场变化率锚定当前观察年份**；切换 `Y` 会重新定义整条情景路径，因此不宜把不同 `Y` 下的结果误认为同一套固定预测。

### 基本符号与单位

| 符号 | 含义 | 单位 |
|---|---|---|
| `P` | 买入总价 | 万日元 |
| `a₀` | 买入时房龄 | 年 |
| `D` | 首付金额 | 万日元 |
| `K_b` | 购房一次性费用 | 万日元 |
| `K_r` | 租房初期**非退还**费用 | 万日元 |
| `L = P − D` | 贷款本金 | 万日元 |
| `N = round(贷款年限 × 12)` | 贷款期数 | 月 |
| `m` | 购入后月数，1～420 | 月 |
| `t = m / 12` | 持有年数，在年末结果中为整数 | 年 |
| `Y` | 当前选定观察/卖房年份 | 年 |
| `G` | 截至 `Y` 年的**累计**市场变化率 | 百分比，计算时除以100 |

## 3. 计算顺序与公式（与 V3.4.6 代码一致）

### 3.1 贷款本金、月供、剩余本金

贷款本金：

```text
L = P - D
r = 年利率(%) / 1200
N = round(贷款年限 × 12)
```

若 `L = 0`，月供 `M = 0`；若 `r = 0`，则 `M = L/N`；否则为**等额本息**：

```text
M = L × r / [1 - (1+r)^(-N)]
```

第 `m` 期还款之后的未还本金：

```text
若 m >= N: B_m = 0
若 r = 0:  B_m = max(0, L - M×m)
否则:      B_m = max(0, L×(1+r)^m - M×[(1+r)^m-1]/r)
```

首月利息 `I₁=Lr`，首月偿还本金 `A₁=M−I₁`。**每月贷款还款金额包含本金和利息，两者都进入现金流；本金的资产价值体现在出售时减去的剩余贷款更少，不再额外加一次本金。**

**例：** 5500万、首付0、1.1%、35年，月供约 **15.78万**，首月利息约 **5.04万**，首月还本约 **10.74万**（四舍五入）。

### 3.2 房龄曲线（蓝线）

先根据情景取 `w`、`k`，定义：

```text
s(a) = 0.1 + 0.9 × exp(-k × a)
R_age(t) = w + (1-w) × s(a₀+t) / s(a₀)
AgePrice_t = P × R_age(t)
```

- `t = 0` 时，`AgePrice_0 = P`，不会重复扣除买入前已存在的房龄折价。
- `w` 被设定为相对稳定价值的权重，建筑老化衰减随时间趋缓；此处指数函数是**老化曲线的数学形状**，并不是假定**整套房产市场价格逐年复利贬值**。
- 这是未经具体地段、面积和真实成交数据校准的**假设曲线**；高龄公寓可能存在修缮、重建、流动性等额外风险，不在函数中。

### 3.3 累计市场变化及预计售价（橙线）

```text
MarketFactor_t = 1 + (G/100) × t/Y
SalePrice_t = max(0, AgePrice_t × MarketFactor_t)
```

`G` 是**截至观察年份 Y 的累计涨跌幅**。例如 `Y=10`、`G=+20%`：第10年市场系数为1.20；第5年为1.10；第20年则外推到1.40。这里是**线性比例路径，不是年化复利**。如果市场因子被外推至负值，代码把售价截断为0：这代表该外推情景已失去合理性，不应视为现实预测。

页面的售价拆分：

```text
房龄影响 = AgePrice_Y - P
市场影响 = SalePrice_Y - AgePrice_Y
预计售价 = P + 房龄影响 + 市场影响
```

注意：这是一种**归因展示的运算顺序**（先房龄、后市场）。价格预测本身并不具备官方统计意义，也没有房产流动性折扣。

### 3.4 买房每个月住房现金支出

对于第 `m` 个月，代码先设 `j=floor((m−1)/12)`（已开始的年度索引）。

```text
贷款支出_m = (m <= N) ? M : 0
修缮费_m = reserve × (1 + reserveRise/100) ^ floor(j/10)

BuyGross_m = 贷款支出_m
           + management
           + 修缮费_m
           + parking
           + tax/12
           + repair/12
```

因此在第1～120个月，修缮费为基础金额；第121～240个月为基础金额×`(1+上调比例)`；第241～360个月再次上调，以此类推。**管理费、停车费、税费、保险/维修在当前版本没有随时间调整。**

若当月收到预计房贷减税 `Credit_m`：

```text
BuyNet_m = BuyGross_m − Credit_m
```

### 3.5 租房每个月住房现金支出

```text
j = floor((m−1)/12)
RentBase_m = rent × (1 + rentRise/100)^j

Renewal_m = RentBase_m × renew    [仅在代码设定的更新月份触发]

RentCash_m = RentBase_m + rentInsurance/12 + Renewal_m
```

代码使用的更新判断是：

```js
m > 12 && ((m - 1) % (renewEvery * 12) === 0)
```

例如更新周期2年时，**代码在第25、49、73…个月计入更新料**，不是第24、48、72个月；这属于待修正的时间偏移。初始签约非退还费用 `rentInitial` 不在月租里重复计算。

### 3.6 住宅贷款减税：三种模式

- **关闭：** 每个月 `Credit_m=0`。
- **手动：** 当 `m` 是年末（12、24、36…）且该年不超过 `manualYears`，一次性计入 `manualCredit` 万；不是每月固定减少 `manualCredit/12`。
- **简化自动：** 当 `m` 是年末且年数不超过 `creditYears`，当前程序执行：

```js
Credit_m = min(taxCapacity, creditCap, B_m) * 0.007
```

**⚠️ 这是当前代码的实际公式，但并非正确的“年度税额上限”应用顺序。** 如果 `taxCapacity=14万`，`creditCap=2000万`，`B_m=5000万`，当前结果是 `14×0.007 = 0.098万`（980日元），而常规概念应先按余额及适用借款上限乘0.7%，再与实际税额上限比较：

```text
正确的简化意图应为：
EstimatedCredit_year = min(0.007 × min(creditCap, B_year_end), taxCapacity)
```

是否实际符合日本住房贷款减税资格、实际税率、额度和年数还应另行核实。**在修正代码前，不要依据自动减税模式的模拟结果做购买决定。**

### 3.7 投资月复利与“谁便宜谁投资”

月投资收益率：

```text
i = (1 + invest/100)^(1/12) - 1
```

初始比较资金基准：

```text
Capital = D + K_b
InitialDifference = Capital - K_r
BuyInvest_0  = max(0, -InitialDifference)
RentInvest_0 = max(0,  InitialDifference)
```

若 `K_r <= Capital`，租房方案初始多出的可投资金额为 `Capital-K_r`，买房方案相对投资余额为0。若 `K_r > Capital`，代码以买房方案正向相对余额来表示租房需要额外投入的资金；**这不是说买房者凭空拿到了现金**，也没有验证真实账户是否足以支付租房押金和签约费。

对每个月 `m`，先对两侧已有的相对投资余额按 `i` 增值，再比较**当月实际现金支出差额**：

```text
δ_m = BuyNet_m - RentCash_m

BuyInvest_m  = BuyInvest_(m-1) × (1+i) + max(0, -δ_m)
RentInvest_m = RentInvest_(m-1) × (1+i) + max(0,  δ_m)
```

含义：

- `δ_m > 0`：买房当月支出高，租房投资差额；
- `δ_m < 0`：租房当月支出高，买房投资差额；
- `δ_m = 0`：当月没有差额投入。

投资在**月末**投入，当月新投入资金不会赚取当月收益；之前账户余额会先计息。双方可能在不同月份各自投资，所以这两个账户余额都可能为正。

**重要：`BuyInvest` 和 `RentInvest` 是相对差额投资账户，不是现实中的全部银行存款或证券余额。** 它们不出现负投资本金，并不表示有能力支付所有买房/租房账单；本工具没有输入收入、现金余额，因此没有资金不足报警功能。

### 3.8 假设在观察年份卖房结清：两种“净资产”

在第 `Y` 年年末（即 `m=12Y`）计算：

```text
卖房后的可回收金额 = SalePrice_Y × (1 - saleFee/100) - B_(12Y)
买房方案的相对净资产 = 卖房后的可回收金额 + BuyInvest_(12Y)
租房方案的相对金融资产 = RentInvest_(12Y)
买房领先金额 = 买房方案的相对净资产 - 租房方案的相对金融资产
```

- **买房净资产：** 假设当年立即出售、结清贷款、扣除按售价比例估算的出售费用，然后加相对投资账户。
- **租房金融净资产：** 租房者持有的**相对初始/每月差额投资账户**，并非全部现金和证券资产。
- “出售相关费用”目前仅按售价比例扣除，**未独立计算转让所得税、贷款提前还清成本、售房固定费用**等。
- 对双方共同拥有且同样投资的额外金融资产，若投资回报、税务、提取时点完全一致，其增值部分在**双方净资产差额中抵消**。

### 3.9 保本售价（盈亏平衡售价）

令两种方案的相对净资产相等：

```text
BreakEven_Y × (1 - saleFee/100) - B_(12Y) + BuyInvest_(12Y)
= RentInvest_(12Y)
```

解得：

```text
BreakEven_Y = [RentInvest_(12Y) - BuyInvest_(12Y) + B_(12Y)]
              / (1 - saleFee/100)
```

这个数的意思是：**假设第Y年真的卖房，成交价至少达到多少，买房的期末相对净资产才能与租房相等。** 它不是贷款银行的“保本价”，也不是预计实际成交价。若未来有不按售价比例计算的卖房税费，必须重新推导公式。

### 3.10 月支出对比区块：首月 / 观察年份月均

**首月实际支出：**

```text
首月买房 = BuyNet_1
首月租房 = RentCash_1
首月差额 = abs(BuyNet_1 - RentCash_1)
```

第 `Y` 年12个月的月均：

```text
买房当年月均 = sum(BuyNet_m，m=12(Y-1)+1…12Y) / 12
租房当年月均 = sum(RentCash_m，同期) / 12
当年月均差额 = abs(买房当年月均 - 租房当年月均)
```

**注意：月均差额不是每个月真正投入的金额。** 租房更新料、年末贷款减税等可能令当年某几个月的支出方向反转。投资账户仍按3.7节逐月计算 `max(0, ±δ_m)`，绝不把「月均差额×12」直接当成实际投资额。

首月现金支出不包含已经在初始资金基准中反映的购房一次性费用和租房初期非退还费用。

## 4. 从输入到结果：完整计算流程

```text
输入房价、房龄、首付、贷款、持有费用、租赁费用、投资假设
             │
             ├─> 贷款本金与等额本息月供、每期余额
             ├─> 房龄曲线＋截至观察年的市场累计变化路径
             └─> 初始相对投资资金 = 首付＋购房费−租房初期费
                         │
                  逐月循环 m=1…420
                         │
                  算买房月支出（含当期减税）
                  算租房月支出（含更新料）
                  双方相对投资账户先复利
                  由支出较低方投入当月差额
                  每12个月记录一次房价、余额、投资账户
                         │
                  观察年 Y 年末按情景卖房结清
                         │
          买房净资产 vs 租房相对金融资产 → 差额、保本售价、图表
```

## 5. 算例：如何自行核对

以默认输入为例（单位：万日元）：`P=5500`、`D=0`、购房费`300`、租房初期费`18`、年利率`1.1%`、35年、管理费`1.5`、修缮费`2`、停车费`2.5`、税`8.4/年`、维修保险`12/年`、租金`18/月`、租房保险`1/年`、投资年化`5%`、减税关闭。

```text
贷款本金 = 5500
月供 ≈ 15.78
第1个月买房总现金支出 ≈ 15.78 + 1.5 + 2 + 2.5 + 8.4/12 + 12/12
                         ≈ 23.48
第1个月租房现金支出 ≈ 18 + 1/12 ≈ 18.08
第1个月由租房方案投入的差额 ≈ 5.40
初始租房相对投资 = 0 + 300 − 18 = 282
月有效投资收益率 ≈ 0.4074%
```

精确输出以网页逐月计算为准；表格显示通常只保留1位小数，可能有四舍五入差异。

## 6. 已知缺陷、限制及计划修正

### ⚠️ 先修正再依赖的实现问题

1. **自动贷款减税的税额上限顺序错误。** 当前源码 `min(taxCapacity, creditCap, debt) * .007`，会把作为“税额上限”的14万先当成“贷款余额上限”。目标应为 `min(.007 * min(creditCap, debt), taxCapacity)`，仍需检查真实个人税务资格。**在修复前不应依赖自动预估结果。**
2. **租房更新料月份偏后一个月。** 当前用 `(m−1) % (renewEvery×12) === 0`，2年周期在第25个月触发。若假定第24个月续约，应按新定义修正，同时避免与第0年初期签约重复。
3. **初始租房费用超过“首付＋购房初期费”时的处理只是差额表示。** 代码以买房相对投资金额补齐差额，而不是核查现金来源。需要增加“资金不足时不参与收益比较”的约束或明示必须另备初始资金。
4. **当市场线性外推因子为负时，代码将售价截断为0。** 极端假设下不宜把第25年/第35年的截断结果当成严肃预测；应提示超出有效情景区间。
5. **界面版本号和 CSV 名称遗留。** V3.4.6 的页面顶部仍写“V3.4.5”，CSV 文件名也含 `v345`；纯展示问题。

### 模型边界（不是代码bug）

- 固定利率、等额本息，不含浮动利率、提前还款、贷款保证费融资及5年/125%规则。
- 公寓房龄折价曲线及“优质地段三情景”为未校准假设，**不是国土交通省或REINS针对具体房源的官方估价**；也未把土地价值、地段溢价和建筑结构用真实样本拆分。
- 税费、管理费、停车费基本按固定金额，修缮积立金仅每10年阶梯式增加；未单独建模一时金、特殊征收、装修大修、交易税、保险续保、更新费用变更等。
- 租房敷金返还或损失未单独建模，初期输入仅指非退还费用。
- 投资复利尚未计入收益税、手续费、市场波动、投资亏损年或真实资金流动性。
- 住宅贷款减税只按模拟年末到账，且没有根据实际税制类别与资格精准计算。
- 卖房费用按售价固定比例，未细分譲渡所得税、仲介费税额、登记与抵押权抹消等。
- 买房净资产是**假设即时卖出后的净值**；真实自住时并没有收到卖房钱。
- 不输入收入、银行流水、现金储备；只能比较相对经济结果，**不能判断支付能力及贷款审批可行性**。
